[网址输入页重设计](https://claude.ai/artifact/UuQgufr1D7PNb8AgQ2b1C4)；设计文档：[网址输入页重设计](https://claude.ai/artifact/6XzaSo3VD3eWdBgwaoG2f5)。
设计与实施状态见 [STATUS.md](../STATUS.md)。颜色、圆角、字号与交互约定沿用添加来源页与云同步页
（[添加来源页](Add-Source-Page-Redesign-Design.md)、[云同步页](Cloud-Sync-Page-Redesign-Design.md)）。

## 一、背景

`VideoGenerationInputView` 曾是一个系统 `Form`，按状态轮流出现五个分组：网址输入框、「检查网站 / 取消检查 / 怎样的页面能生成？」、检查进度、
状态（结论 + 取页方式 + coin + 生成按钮 + 提交结果）、状态（错误 + 重试）。三种类型共用同一页，只换导航栏标题「视频 / 漫画 / 书籍」。

- 添加来源页已是自绘大标题与卡片，在同一层 sheet 里接着出现的这一页还是系统表单。
- 标题只有一个字，看不出这页在做什么。
- 结论、提交前选项、提交结果挤在一个分组里，可以生成时有八行，主按钮「生成规则」是最后一行蓝字。
- 颜色用系统绿 / 橙 / 红，不是 `CatalogPalette` 的取值。
- 网址要手打或长按粘贴，没有粘贴按钮。
- 网址写错与页面不合格是两个同名分组「状态」，看起来是同一类事。
- 引导屏（首次必过一屏与回看）也是系统表单，夹在两屏新样式之间。

## 二、入口、流程与范围

只有一个入口：添加来源页选了类型之后在同一层 sheet 里接着出现；首次先过引导屏。流程：贴网址 → 本机检查（不联网到服务器、不花 coin）→ 看结论 →
可以生成时选取页方式、滑动提交 → 提交成功停 1.2 秒后整个 sheet 收起回来源页，其他结果留在本页。

本文覆盖输入页全部状态与引导屏的外观（2026-10-06 用户裁定六项全取 A）。引导屏的文案、版本号与「首次必过」的判定（`BC-PAGE-060`）不动。

## 三、页面内容

页面跟随系统深浅，底色与卡片底取系统分组背景，颜色全部取 `CatalogPalette`，不新增。总原则：**一个阶段一张卡，任何时候页面上只有一个主控件**。

| 块 | 内容 | 取值与组件 |
| --- | --- | --- |
| 顶部 | 左上「关闭」；自绘大标题「生成视频规则」（按类型换词），标题前一枚 28pt 类型色图标圆；一句说明「贴一个带页码的列表页地址，先在本机检查，不花 coin。」。检查中、出了结论或结果之后说明句收起（`showsIntro = result == nil && isChecking == false`） | `largeTitle` heavy；图标圆取 `CatalogKindStyle.accent` 字 + 16% 底 |
| 网址卡 | 圆角 18 卡片：左侧链接图标、输入框（占位「带页码的列表页地址」）、右侧系统粘贴按钮（输入为空时显示，剪贴板为空时由系统按钮自行禁用；点了即填入并开始检查）或清除 ⓧ；检查中与提交中整卡变淡、禁用。卡下一行链接「怎样的页面能生成？」，出了结论后收起 | 系统 `PasteButton`（不弹授权）；链接动作蓝，叠一层引导屏 |
| 主按钮 | 蓝色胶囊「检查网站」，空输入时变淡禁用；手打的网址点按钮或回车开始检查。检查中换次级样式「取消检查」；还没看清换「再检查一次」 | 高 50 |
| 进度卡 | 检查中网址卡下一张卡：四步纵向清单（校验地址 → 隔离加载页面 → 检查列表结构 → 确认页面上的列表），做完的打勾、当前的转圈、未到的灰；卡下一句「只检查这一个地址，不搜索、不推荐别的页面。」 | 卡片组行；转圈取动作蓝 |
| 结论卡 | 检查完换成结论卡，与云同步页状态卡同一套 `StatusCardView`（56pt 圆图标 + 标题 + 一句原因；图标蓝取 `settingsIcon`，浅色 #2563EB / 深色 #8AB6FF，与按钮的添加蓝 #2563EB 在深色下是两种蓝，与云同步页一致）：**可以生成**（蓝 ✓）、**这一页不能用**（警示橙 ✗，原因按 8 种换词，卡内链接「看看怎样的页面能生成」，卡下一句「改一下上面的网址，就会回到「检查网站」」）、**还没看清这一页**（警示橙 ?）、**有反爬验证，可以直接提交**（蓝盾）。警示态卡加警示色描边 | 共用 `StatusCardView`；不用绿、不用红 |
| 取页方式卡 | 只在可提交时出现。分区标题「取页方式」+ 卡片：两个胶囊按钮「普通 · 100 coin」「困难 · 300 coin」。普通 = 素底，选中时添加蓝 12% 底 + 蓝字 + 蓝描边；困难 = 粉彩渐变淡底（`CatalogPalette.spectrumFill`，#7FA8F7 → #B9A3F5 → #F2A8C8 → #F8C38F 的 16%）+ 渐变发光描边（`SpectrumGlowBorder`，饱和渐变 #2563EB → #7C3AED → #E0457B → #F28C28 沿胶囊描一圈、方向约 2 秒来回摆动一次、外加粉彩光晕，与内购页套餐按钮同一种语言），选中时描边更粗更亮、字用饱和渐变；不用黄 / 橙。系统「减弱动态效果」打开时描边不摆动。卡内始终有一句档位说明（普通档 `generation_input_tier_normal_footer`、困难档 `video_preflight_tier_hard_footer`），困难档且结论是反爬时再多一句警示色。卡内最后一行是地区生成成功率（[Campaign-And-Rate-Notices-Design.md](Campaign-And-Rate-Notices-Design.md) 第三节），取不到不显示。卡片组脚注一行（`generation_input_balance_footer`）：「当前余额 M · 生成可能失败，失败也会扣 coin。如果这个网址已有现成规则会直接取用，只扣 N（自己 7 天内生成的不扣）。」，N 取服务端的取用价；余额未知时不写余额那段，没有钱包对象整行不出 | 新组件 `GenerationTierPicker`；价格取服务端 `pricing` |
| 滑动确认 | 可提交时主控件是滑动确认：胶囊轨道、左端 44pt 圆形滑块带箭头、中间「滑动生成 · 100 coin」（价格随档位变）；拖到右端打一次触觉反馈再提交，没拖到底松手弹回；拖动中跟手，松手才走弹簧。两套视觉：普通档添加蓝 12% 底、蓝滑块白箭头、蓝字；困难档粉彩渐变淡底铺流光点阵（`DotMatrixTrack`，一道光斑约 2 秒扫一遍，扫过的点变亮略变大）+ 饱和渐变文字与滑块，不加渐变发光描边（描边只给困难按钮；系统「减弱动态效果」打开、禁用或进行中时静止）。提交中滑块停在右端内转圈、文字换「正在提交…」。检查时已知有现成规则时写「滑动取用现成规则 · N coin」（N 取服务端报的取用价，为 0 时写「滑动取回我的规则 · 免费」，见下一行「现成规则」）；提交失败时写「滑动再试一次 · N coin」。取用之后不再有滑动确认（见「提交结果」） | 新组件 `SlideToConfirmControl`；只有扣 coin 的动作要滑 |
| 现成规则（2026-10-19 用户定） | 结论为可以生成或反爬放行时，App 同时问服务端这个网址有没有可以直接取用的规则（只查不扣费、不下发规则，见第六节）。有的话：结论卡下多一张信息卡（蓝 ✓ 小图标 +「这个网址已有现成规则」+ 一句「直接取用只扣 N coin，不用重新生成。取用后规则在目录「我的生成」里。」，本人 7 天内生成的写「是你 7 天内生成的，取回免费。」）；取页方式卡不出（取用与档位无关）；主控件是「滑动取用现成规则 · N coin」；滑杆下一行小字链接「不用现成的，重新生成」，点了走下面的重新生成面板。查询还没回来时按没有现成规则显示，回来后再换；查询失败、未登录或服务端判定要排队生成时照常显示取页方式与「滑动生成」 | 信息卡是本页自绘的小卡（28pt 圆图标 + `subheadline` 标题 + `footnote` 说明），不是 `StatusCardView`；链接动作蓝 |
| 提交结果 | 替换结论卡：**生成任务已提交**（蓝纸飞机，「生成完成后会出现在规则目录「我的生成」里，从那里添加。」+ 小字「正在回到来源页…」）；**规则已存在**（蓝 ✓，写规则名与扣费；主控件是蓝色胶囊按钮「添加为来源」，点了走与规则目录「添加」同一条路径加进来源、选中并收起整个 sheet，不再扣 coin；已添加过的写「已在来源里」并禁用；按钮下一行小字链接「规则用不了？重新生成」，点了走重新生成面板。不再出现「滑动重新生成」）；**需要登录 / 任务已达上限 / 上一个任务还没完成 / 提交太频繁 / coin 不足**（警示橙，无主控件，coin 不足的文案带「看完激励广告可获得 coin」）；**提交没有成功**（警示橙，滑动再试一次；文案按成因分三句——传输失败提示检查网络、本机预检拒绝提示重新检查网址、其余带服务端错误码，`submissionFailureMessage`） | 同一套状态卡 |
| 重新生成面板（2026-10-19 用户定） | 从「不用现成的，重新生成」或「规则用不了？重新生成」进来：拉起本页自己的底部面板（不用系统确认框）——抓手、28pt 动作蓝图标圆 + 22pt 标题「重新生成这条规则」、一句「会再扣一次 coin。建议先添加试用，确定用不了再重新生成。」、分区标题「取页方式」与取页方式卡（两个胶囊按钮、档位说明、成功率一行，与上面同一张）、余额说明、主控件「滑动重新生成 · N coin」（随档位换价与样式），最下一个动作蓝文字按钮「取消」。滑到底即提交（`refresh`），面板收起，结果照常换成提交结果卡 | 复用 `GenerationTierPicker`、`SlideToConfirmControl`；面板为 `.sheet`，高 0.66 屏（`.fraction(0.66)`），可拉到全高 |
| 网址错误 | 网址无效 / 非 HTTP / 不安全 / 非 HTML / 404 / 403 / 429 / 5xx / 请求失败：不出卡，网址卡加警示色描边，卡下一行警示色小字；主按钮回到「检查网站」 | 警示色文字与描边 |

- 改网址即清空结论与提交状态，回到只有网址卡 + 「检查网站」的状态（与现状相同）。
- 任务客户端未接线时（只在测试替身下出现）主控件禁用并保留现有一句说明。Debug 演示模式（`-BrowseCraftDemoMode`）经 `SourceDiscoveryService` 的 `assessmentOverride` 跳过本机检查，网址直接通过。
- **引导屏**：自绘大标题「怎样的页面能生成」，一句说明，顶部插画不动；「两条要求」做成两行卡片组（32pt 图标方块 + 标题 + 说明），组下一句提醒；
  「例子」两行（✗ 警示橙 / ✓ 动作蓝）；「怎么找」三行带序号圆；底部蓝色主按钮「我找到了这样的页面」或「知道了」。首屏左上「取消」关掉整个流程，回看形态没有取消。

## 四、不改的东西

- 预检的判定与四步流程、结论与原因的含义、反爬放行、提交串的取法（fwq `BC-PREFLIGHT-*`；困难模式档位的条款仍在 fwq 的待实施设计里，尚无定义点，本文不引用）。
  预检取页的超时与引擎直接请求取页对齐（fwq `APP-MEMO-044`）：单页 25 秒（`VideoGenerationInputSamplingPolicy.requestTimeoutSeconds`、`PreflightPageRequest.timeoutSeconds` 缺省值）、全局 30 秒（`globalDeadlineSeconds`）。
- 提交逻辑、提交结果的来源、价格与余额的来源；提交成功 1.2 秒后自动回来源页；规则已存在时不**自动**添加成来源（2026-10-03 裁定），由用户点「添加为来源」手动添加。
- 引导屏的文案、版本号与「首次必过」的判定；目录页失败行与空状态里打开引导屏的入口。
- 「离开即结束整个流程」的关闭纪律；输入页不能退回改类型。

- `BrowseCraft/Features/Sources/AddSource/EntryPageGuideView.swift`：引导屏按第三节重画；`EntryPageGuideFlowView` 不动。
- `BrowseCraft/Features/Shared/StatusCardView.swift`：从云同步页抽出的状态卡，云同步页改为复用。
- `BrowseCraft/Features/Shared/SpectrumGlowBorder.swift`：渐变发光描边，只给困难按钮。
- `BrowseCraft/Features/Shared/DotMatrixTrack.swift`：流光点阵（`TimelineView` 驱动 `Canvas`），只给困难档滑动确认用。

- 现成规则：`BrowseCraftAPIKit` 新增 `GET /v1/rule-generations/reuse-preview` 客户端；App 端口 `GenerationReusePreviewing`（`APIKitVideoGenerationTaskClient` 同时实现，提交与预览共用地区来源），`CreateVideoGenerationTaskUseCase.reusePreview`，`SourcesViewModel` 在预检可提交时查一次（与提交用同一个 `acceptLanguage`）；`VideoGenerationInputView` 按第三节加信息卡、取用滑杆、「添加为来源」按钮与两处重新生成链接，重新生成面板是新视图 `RegenerateRuleSheet`；`source_added` 的 `entry` 加 `generation_reuse`（先登记进埋点字典）。

## 六、服务端依赖（PortalCore）

- `GET /v1/rule-generations/reuse-preview?entryURL=…&sourceKind=…&acceptLanguage=…`：要登录；与提交走同一个复用判定，只回 `{"reusable": true|false, "coinCost": N}`，不下发规则、不扣费、不排队；本人 7 天内的为 `coinCost` 0，公共规则为取用价，别人 7 天内生成的与没有规则的都是 `reusable` false。只透露「有没有、多少钱」，规则本身仍只能经提交取用并扣费（PortalCore 发布前检查清单第 9 项）。
- 取用的幂等键（App 侧落点，实施状态见 [STATUS.md](../STATUS.md) 第 2 节）：服务端收 `Idempotency-Key` 请求头（`[A-Za-z0-9._:-]{1,128}`），同用户、同网址、同键 24 小时内重发只扣一次并返回同样的 `coinCharged`。
  App 侧：输入页每次滑动提交（取用或生成，重新生成除外）生成一个 UUID 键，同一份预检结果上提交失败后再滑沿用同一键，换网址、重新检查或得到非失败结局后作废；
  键经 `CreateVideoGenerationTaskUseCase` 与 `VideoGenerationTaskCreating` 原样交给 APIKit 进请求头。服务端只在取用路径看它，所以普通生成也带上没有副作用，
  预览没查到、服务端却取用了的那次同样受保护；不带键的行为不变（再扣一次）。

## 七、真机验收清单

- 网址错误不出卡；困难档的渐变描边与流光点阵；滑动确认拖一半弹回；引导屏回看形态。深色模式整页看一遍。
- 贴一个已有公共规则的网址，检查后出「已有现成规则」信息卡与「滑动取用现成规则 · 100 coin」、没有取页方式卡；取用后点「添加为来源」进了来源并收起 sheet、余额只扣一次；两处重新生成链接都先拉起重新生成面板、点取消不扣费。
