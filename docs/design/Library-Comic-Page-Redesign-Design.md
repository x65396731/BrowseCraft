# 库页漫画库的视觉与信息结构重设计

设计稿（画布，含めちゃコミック实际效果、有分类的来源、深色、长按菜单、骨架、空、失败、尺寸与取值，共 8 张）：
[库页漫画库重设计](https://claude.ai/artifact/LcVBKuQfJkZEreE5acyhRL)；设计文档：[库页漫画库重设计](https://claude.ai/artifact/2V7wRwnvGt5h4RrkNCQExB)。
设计与实施状态见 [STATUS.md](../STATUS.md)。外壳（眉行、大标题、圆按钮、贴顶芯片、各状态、分页脚）与颜色、圆角、字号沿用
[库页视频库](Library-Video-Page-Redesign-Design.md)，继续瓷砖与进度文案沿用 [漫画详情页](Comic-Detail-Page-Redesign-Design.md)，本页不新增色值。

## 一、背景

库页视频库那轮把外壳改成了三种类型共用的统一语言，但漫画与书籍的网格没动：还是 `ComicLibraryCardView` 三列封面卡，封面圆角 6、12pt 粗体标题、
写死的蓝紫色 `latestText`、每张封面右上一个黑圈爱心。书籍复用同一张卡，所以漫画库和书籍库长得一样，和视频库的区别只是列数。

漫画库跟视频库的使用方式不同，版式该跟着不同：

- 漫画是逐章追的。回到库页最常问的是「这部我读到哪了」「更新了没」，不是「有几集」。现在读过的作品在库页上没有任何痕迹。
- 漫画靠封面识别，但标题长（めちゃコミック的标题三四十字），三列下两行标题前面都被截断。
- 「更新至第94话」是漫画列表最有用的一行，现在是写死的蓝紫小字，与类型色（紫）无关。
- 「上次看到」瓷砖只接了视频历史，漫画来源上永远不出；要接着读只能去历史页。
- 漫画卡片还在用视频那轮已经删掉的 `libraryTitleText`，当时就说好「漫画立项时一并删」。

视频是两列海报墙、集数徽章压封面、标题两行；漫画是三列封面墙、封面下标题 + 最新话两行、读过的作品封面上压进度角标、「上次读到」瓷砖。
两种密度、两种封面上的信息，就是两种版式。

## 二、规则与本机实际给什么数据

**列表项**（`ContentItem`，规则列表 `fields`）：漫画列表规则能给的只有五个字段，没有作者、状态、评分、更新时间。

| 字段 | 规则里的来源 | 三条漫画规则的现状 | 页面怎么用 |
| --- | --- | --- | --- |
| 标题 | `title`（必有） | 都有；めちゃコミック的很长 | 封面下第一行，最多两行 |
| 封面 | `cover`（可选） | 都有（めちゃコミック列表封面是真封面，详情页的 og:image 才是 logo） | 封面 2:3；没有退到 `ComicListPlaceholder` |
| 详情地址 | `detailURL`（必有） | 都有 | 点卡进详情；也是和收藏、历史对上的键（`item.id`） |
| 最新话 | `latestText`（可选） | MYCOMIC「第07话」「短篇 [完]」对；sfacg 是整条卡片文字；めちゃコミック是类型标签「女性漫画 恋愛 めちゃコミックオリジナル」（fwq 需求四已提） | 封面下第二行，类型色一行截断；没有不出 |
| 语言 / 编号 | `language` `idCode` | 有 | 不显示 |

**漫画章节历史**（本机 `comic_chapter_history`，一章一条）：按来源过滤就能得到这个来源下读过的每一章，按 `comicItemID` 分组取最近一条就是「每部读到哪」，
全局最近一条就是「上次读到」。字段里有章节名、`lastPageIndex`、漫画详情那轮新加的 `pageCount`、上次页面的图、封面、访问时间；
章节名走同一个 `ComicChapterTitleParser` 就能缩成「4-2」。现在 `LibraryViewModel` 只读视频历史（「上次看到」瓷砖），漫画历史要加一个按来源取全部的只读查询。

**收藏**：`favoriteItemIDs` 已经在库页里，按 `item.id` 判。

**其他外壳数据**（与视频库同）：分类芯片看列表规则个数（めちゃコミック 1 个，不出）；搜索按钮看规则是否声明 search（有）；
账号按钮看有无登录配置（めちゃコミック有 `loginURL`，出）；分页脚看规则是否分页（有）。

线上目录里漫画只有めちゃコミック一条；模拟器上已加它，并有一条《青い瞳の花嫁》第 4-2 话第 6 / 58 页的历史，足够看到瓷砖与进度角标。

## 三、入口、相邻页面与范围

- **入口**：底栏第三个标签「库」，当前来源是漫画时走本版式；来源页点来源、收藏页与历史页「在库中查看来源」都落到这里。
- **出口**：点封面进漫画详情与章节页；「上次读到」瓷砖直接进阅读器，与历史页点行同一条路；左上搜索弹出来源内搜索页（结果复用本页的卡片）；账号按钮打开来源登录页。
- **相邻**：左邻收藏页、右邻历史页，都是封面卡片行；下一页是漫画详情页（紫调淡底头部）。本页的紫色只用在眉行图标、最新话、进度角标、已收藏爱心、瓷砖和选中芯片上，进详情页时色调连贯。
- **范围**：只改当前来源是漫画时的正文——网格、卡片、「上次读到」瓷砖、骨架与空态插画，外加漫画历史的一个只读查询。外壳照视频库那轮，换 `CatalogKindStyle` 即换色。
- **不在范围**：书籍库（另立项，本轮之后书籍暂时还用旧卡片）、漫画详情页、阅读器、搜索页外壳、列表数据与分页；底栏（`RootView` 的系统 `TabView`，五页共用，画布上照视频库画布原样画，只作位置参照）。

## 四、页面结构

页面跟随系统深浅，底色取页面底，隐藏系统导航栏。从上到下（1、2、4、6 与视频库同形，只换类型色）：

| 顺序 | 块 | 内容 | 什么时候出现 |
| --- | --- | --- | --- |
| 1 | 顶部 | 眉行「气泡 漫画 · 主机名」（图标取漫画类型色）+ 大标题 = 来源名 + 右侧搜索 / 账号圆按钮 | 一直；两个按钮各自按规则有无 |
| 2 | 分类条 | 贴顶胶囊芯片，选中段漫画类型色底 | 来源有两个以上列表页时 |
| 3 | 上次读到 | 漫画类型色的深色瓷砖：封面 72×100、「上次读到」、作品名、「4-2 真夜中の逢瀬 · 6 / 58 页」、进度条、时刻；点了直接进阅读器 | 当前来源有漫画历史时 |
| 4 | 分类出错横幅 | 警示色淡底一行 | 有内容但当前分类报错时 |
| 5 | 封面墙 | 三列、列距 12、行距 18；封面 2:3 圆角 10；读过的作品封面左下压「读到 4-2」角标、已收藏右上小爱心；封面下标题两行 + 最新话一行 | 有内容时 |
| 6 | 分页脚 | 网格下方一行小字 | 规则支持分页且有内容时 |
| — | 骨架 / 空 / 失败 / 切源 | 见第七节 | 对应状态时整页只出一种 |

下拉刷新、滑到底加载下一页两条路不变。页边距左右 20pt。与视频库的区别在第 3、5 两块：瓷砖读漫画历史、写章节与页数；
封面墙三列、封面上压的是每部的阅读进度而不是集数，最新话放在封面下。

## 五、封面卡片

一张卡片 = 封面 + 封面下两行文字；封面上只压「读到哪」和「已收藏」两个小标记，没读过、没收藏的封面是干净的。

| 位置 | 内容 | 取值 |
| --- | --- | --- |
| 封面 | 2:3，宽随三列算出（iPhone 17 Pro 约 108×162pt）；`ItemThumbnailImageView` 走现有封面管线，请求配置取规则的图片请求配置；无封面退回 `ComicListPlaceholder` | 圆角 10，不描边、不投影 |
| 封面左下 · 进度角标 | 这部读过时「读到 4-2」（章节名经 `ComicChapterTitleParser` 缩成编号，解不出就写原章节名一行截断）；没读过不出 | 固定色胶囊：底 #B79CFF 字 #141210，`caption2` bold，高 20、左右 8、离封面边 6；与视频集数徽章同一种做法、换漫画的固定取值 |
| 封面右上 · 爱心 | 只在已收藏时显示：`TabFavorites` 14pt 实心漫画固定紫 #B79CFF 在 26pt 黑 40% 圆里；未收藏不压爱心 | 收藏 / 取消走长按菜单，与视频库同一套菜单 |
| 标题 | 作品名 `footnote` semibold 主文字色，两行定高，同一行的卡片底边对齐 | 封面下 6pt |
| 最新话 | `latestText` 照原文一行截断，`caption2` 漫画类型色（浅 #6D4FD6 / 深 #B79CFF）；没有不出，行位留空让同行对齐 | 标题下 2pt |
| 整张卡片 | 点 = 进漫画详情；长按菜单「打开」「收藏 / 取消收藏」，读过的再加「继续读 · 4-2」直接进阅读器；预览按封面圆角裁 | 按下整卡变淡 |

- 三列一屏约 9 张（视频是 4–6 张）：漫画库条目多、靠封面扫，密度就是两种版式的第一个区别。
- 进度角标是第二个区别：视频封面上压的是规则给的集数（这部有多少），漫画封面上压的是本机历史（我读到哪）；规则给的最新话放到封面下面做第二行。
- iPad 与横屏：列数按最小宽 104pt 自适应。搜索结果复用同一张卡片。

## 六、「上次读到」瓷砖

与视频库的「上次看到」同一张 `HistoryContinueTileView`，换漫画的来源瓷砖样式（底 #221E33、光圈与小字 #B79CFF）。

- **条件**：当前来源的漫画章节历史里取访问时间最近一条；切来源重取，从阅读器 / 详情页回来、回到库标签、来源页连带删除历史之后刷新（与视频瓷砖同一组时机）。属于来源、不属于分类。
- **样子**：左封面 72×100 圆角 12（历史里的 `coverURL`）；右侧「上次读到」紫小字、作品名 `headline` bold 两行、第三行「4-2 真夜中の逢瀬 · 6 / 58 页」
  （章节名经解析器得编号与话名；没有 `pageCount` 写「第 6 页」）、4pt 进度条（有页数时）、底行只写时刻。
- **点击**：整张瓷砖 = 用历史记录直接开阅读器，与历史页点行同一条路径（`ReaderView` 的历史入口）；长按菜单「继续读」「打开作品」（进详情）。不在这里删历史。
- **不出现**：没有漫画历史、来源切换中、搜索页。骨架 / 空 / 失败态下有历史照样显示。
- **数据**：视频库那轮已经说过「漫画将来用同一个查询换类型即可」：`LibraryViewModel` 加读漫画历史的只读查询，一次按来源取全部，
  瓷砖取最近一条、进度角标按 `comicItemID` 取各自最近一条，同一次读。

## 七、其余状态

正文同一时刻只出一种版面（`LibraryBodyState` 不动）；眉行、大标题、分类条与「上次读到」瓷砖在所有状态下照常。

| 场景 | 显示 |
| --- | --- |
| 首屏加载 | 骨架与封面墙同形：三列封面色块（圆角 10）+ 两行标题条，呼吸动画；`LibrarySkeletonGridView` 按类型选列数，漫画 9 张 |
| 取回来是空的 | `LibraryPlaceholderView`：插画 `EmptyStateLibraryComic`（看板娘把一叠淡色空白封面的单行本抱在胸前，本页自己的图；库页空态按来源类型选插画，视频仍是 `EmptyStateLibraryVideo`）+「还没有内容」+ 一句说明 +「下拉可重新载入」 |
| 第 1 页失败 | 同上，插画 `EmptyStateOffline` +「载入失败」+ 错误原因 +「下拉重试」 |
| 有内容但本分类报错 | 警示色淡底横幅，在网格上方（现有 `LibraryTabErrorBanner`） |
| 切换来源 | 旧列表留在屏上盖页面底 82% + 居中状态卡（现有） |
| 翻页中 / 还有下一页 / 已到底 | 分页脚三条文案（现有） |
| 下拉刷新 | 系统下拉控件；刷新中网格不换骨架 |
| 来源需要登录 | 账号按钮空心；列表照规则给的结果显示（现状） |
| 深色模式 | 页面底、芯片随系统；瓷砖与进度角标是固定深色取值，两种模式下一样 |

空状态插画与其余插画同规格（同一个看板娘、即梦出图、透明底、540px 高、按 180pt 显示，画面内不含文字）；即梦设定与提示词在画布「漫画库空状态插画 · 即梦设定」画板；已出图入库（构思 A「抱在胸前」）。

## 八、每个元素的数据来源与缺省

每个元素都是有数据才显示，没有就整块不出、不留空位。最后一列是めちゃコミック（线上唯一的漫画来源）上会看到什么。

| 元素 | 数据来源 | 没有时 | めちゃコミック实际 |
| --- | --- | --- | --- |
| 封面 | 列表规则 `cover` | 退回 `ComicListPlaceholder` | 有，真封面 |
| 标题 | 列表规则 `title` | — | 有，很长，两行截断 |
| 最新话 | 列表规则 `latestText` | 不出，行位留空 | 有，但内容是类型标签；照原文显示，内容对不对由 fwq 需求四修 |
| 进度角标 | 本机漫画章节历史按 `comicItemID` 的最近一条 | 不出 | 《青い瞳の花嫁》有「读到 4-2」，其余没有 |
| 已收藏爱心 | `favoriteItemIDs` | 不出 | 试收藏过一部 |
| 「上次读到」瓷砖 | 本机漫画章节历史最近一条 | 不出 | 有：4-2 真夜中の逢瀬 · 6 / 58 页 |
| 分类芯片 | 列表规则个数 ≥ 2 | 不出 | 1 个，不出 |
| 搜索按钮 | 规则声明 search | 不出 | 有 |
| 账号按钮 | 来源有登录配置 | 不出 | 有（`loginURL`） |
| 分页脚 | 规则支持分页 | 不出 | 有 |

所以めちゃコミック实际看到的是：没有芯片、两个圆按钮都有、瓷砖一张、九张封面里一张有进度角标、封面下第二行是类型标签。
最新话是不是「更新到哪」是 fwq 侧的事，App 不改规则、只按有无显示。

## 九、要追加的字段与查询

不加表、不加列、不动 Core 与规则；只加一个只读查询和一次复用。

| 项 | 在哪 | 为什么 |
| --- | --- | --- |
| 按来源取全部漫画章节历史 | `LibraryPersistenceCoordinator` 加漫画历史仓储与一个只读入口（现有 `fetchHistory(userID:)` 按 `sourceID` 筛，或仓储加按来源的查询）；`LibraryViewModel` 存「最近一条」与「按 `comicItemID` 的最近一条」字典，与视频瓷砖同一组刷新时机 | 瓷砖与进度角标；一次读全部，不按卡片逐条查 |
| 章节名缩成编号 | 复用漫画详情那轮的 `ComicChapterTitleParser` | 角标「读到 4-2」、瓷砖第三行 |
| 页数进度 | 历史里已有 `lastPageIndex` 与 `pageCount` | 瓷砖「6 / 58 页」与进度条；没有页数写「第 6 页」 |
| 阅读器入口 | `LibraryView` 已有漫画详情的导航，加一条「用历史开阅读器」的导航（`ReaderView` 的历史入口，历史页已在用） | 瓷砖与长按「继续读」 |

**向 fwq 提的**：没有新的。最新话的取值问题已在漫画详情那份需求文本的需求四里。

**候选、本轮不做**：「有更新」标记（本机记上次看到的 `latestText`，变了就标红点）要一张新表记每部的最新话，且在现有来源上 `latestText` 本身就不是更新状态，等 fwq 需求四落地后再立项。

## 十一、裁定

2026-10-08 用户裁定七项全取 A：三列封面墙；封面上压本机阅读进度、最新话放封面下；只在已收藏时显示小爱心、收藏动作走长按菜单；加「上次读到」瓷砖；
角标文字「读到 4-2」；长按菜单加「继续读 · 4-2」；本轮出空状态插画 EmptyStateLibraryComic（实施时新增的资产）。

## 十二、不改的东西

- 列表数据、分页、分类缓存、切换来源、收藏切换、搜索、登录与凭据；`LibraryBodyState` 五种状态与优先级；下拉刷新与触底加载两条路。
- 视频库与书籍库（书籍继续用旧卡片到它自己立项）；漫画详情页与阅读器；搜索页外壳；底栏（系统 `TabView`，不随来源类型变）。
- App 不提供规则创建或编辑入口（`BCA-UI-003`）；`latestText` 等字段有无由规则决定。

## 十三、实现位置
