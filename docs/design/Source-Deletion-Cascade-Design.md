# 删除来源时保留历史与收藏

设计与实施状态见 [STATUS.md](../STATUS.md)。数据层的条款定义点在
[数据库说明](../../BrowseCraft/Infrastructure/Database/README.md)「Source 删除规则」（`BCA-DB-004`、`BCA-DB-005`），本文写范围、各条删除路径的处理、
被删来源的条目怎么显示与打开、界面与实现清单，不复述条款正文。文件名沿用连带删除时期的名字，以免各处链接失效。

## 一、背景

删除来源曾在同一写事务里连带删除该来源的三张历史表记录，并给它的收藏写删除标记、同步到其他设备。
收藏页与历史页有了面容 ID 锁定（[收藏与历史的面容 ID 锁定](Content-Lock-Design.md)）之后，2026-10-17 用户裁定改为保留：
历史与收藏是用户自己的记录，删来源只是不再用这个网站，不该把看过的、想看的一起丢掉；担心被旁人看到的，交给锁定。

## 二、删什么、不删什么

用户删除一个来源时，在同一个写事务里：

| 数据 | 处理 |
| --- | --- |
| 来源 | 软删除并写入同步队列（内置来源不入队） |
| 库的当前选择 | 当前选择正好是它时清空（`BCA-DB-004`） |
| 漫画、视频、书籍三张历史表 | 保留，不动 |
| 收藏 | 保留：不写删除标记、不入同步队列，收藏汇总不变 |
| 临时资源历史 | 不涉及：它没有来源 |
| 站点书续读位置与书签 | 不动 |
| 来源的登录凭据 | 不涉及：只存在内存里，重启即失 |

## 三、被删来源的条目

- **显示**：收藏页与历史页照常列出，来源名后加「· 来源已删除」，整行变淡（两页设计文档里既有的状态）。
- **打开**：点行用条目里保存的来源快照（`SourceSnapshot`、`FavoriteSourceSnapshot`）打开详情、阅读器或播放器，与来源在册时同一条路径。
  快照在收藏与写历史时随条目保存，含完整的来源配置，所以详情、章节、阅读与播放都可用。
- **删除**：左滑与长按照常可以逐条取消收藏、删除记录。
- **重新添加同一个来源**：来源 ID 取规则目录条目的 ID，重新添加后 ID 相同，这些条目自动回到正常状态，不再显示「来源已删除」。
- **同步**：收藏照常随 iCloud 同步，其他设备上同样显示为「来源已删除」。续看位置同步只处理本机在册来源的历史
  （[续看位置同步](History-Resume-Sync-Design.md)第三节）：被删来源的历史留在本机，不再上传、不登记为删除；重新添加来源后，有新进度的作品照常上传。

已知代价（2026-10-17 用户接受）：

- **来源位置可被绕过**：删掉来源腾出位置后，仍能通过收藏与历史打开该来源的作品，详情、章节、阅读与播放都可用，不占位置。
  已暂停（位置不够）的来源仍然要先启用才能打开，两者不一致。
- **快照里的规则不跟随目录更新**：它停在收藏或写历史那一刻；网站改版后可能打不开，重新添加来源即可。
- **被删来源的条目一直留在两页**：只能逐条删除，没有批量清理入口。

## 四、各条删除路径

| 路径 | 入口 | 处理 |
| --- | --- | --- |
| 用户删除 | 来源页左滑与长按「删除来源」；删除「我的生成」规则与个人规则过期（`deleteSourcesWithoutUndo`） | 按第二节：只删来源并清空库的当前选择 |
| iCloud 应用远端删除 | 其他设备删除来源，本机下载到带删除时间的来源记录（`GRDBSourceSyncLocalStore` 写入） | 写入删除，并按 `BCA-DB-004` 清空库的当前选择；历史与收藏不动 |
| iCloud 区域被清除 | 用户在系统设置里清除 iCloud 数据（`GRDBCloudSyncEngineStore` 的清除分支） | 不变：硬删来源与全部收藏，历史保留 |
| 只用 iCloud 数据 | 登录合并时选择只用云端数据（`GRDBCloudAccountPartitionStore`） | 不变：硬删来源与全部收藏、清空选择，历史保留 |

后两条是账户级操作，范围与「删一个来源」不同，本设计不改。

还在用连带删除版本的设备与本机混用时：那台设备删除来源会把收藏删除标记同步过来，本机照常删掉那些收藏；
它收到本机的来源删除时，会删掉它本机该来源的历史。两边都升级后不再出现。

## 五、撤销

用户在来源页删除后，底部出现与收藏页、历史页同一个反色提示条「已删除「来源名」 · 撤销」（`ContentUndoBanner`），约 4 秒后消失；不弹确认。

- **留底**：删除的写事务交回 `SourceDeletionReceipt`——来源记录原样（含启用状态）与删除前库的当前选择（来源 ID 与列表位置）。
  历史与收藏没有被删，不在留底里。
- **撤销写回**：在一个写事务里把来源恢复为在册（清掉删除时间、更新时间取当前时间），非内置来源以当前时间重新写入同步队列为更新。
  同步队列按「更新时间较新的更新覆盖较旧的删除」合并，删除若还没上传，队列里留下的就是更新。
- **当前选择与来源位置**：删除前它是当前来源，撤销后改回当前来源并恢复列表位置；删除时若有已暂停的来源补上了位置，撤销后按位置规则重新归置。
- **推迟同步通知**：删除成功后先不发本地变更通知，等撤销提示消失、被新的撤销提示替换或离开来源页时再发；撤销时不发删除的通知，只在写回后照常通知。
  内置来源不入队，删除与撤销都不必通知。
- **不撤销的**：iCloud 应用远端删除不给撤销；撤销窗口结束、App 被关掉或切走后不能再撤销。

## 六、界面

- 来源页底部说明写「删除来源后，它的阅读 / 观看历史和收藏仍会保留。」三语。
- 删除与撤销后 `RootView` 重新载入历史页与收藏页，让被删来源的行变为「来源已删除」或恢复正常。库页的收藏标记与「上次看到」瓷砖只看当前来源，不受影响，不再刷新。

## 七、实现位置

- `BrowseCraft/Infrastructure/Database/Repositories/GRDBSourceRepository.swift`：删除只软删来源、清空库的当前选择、非内置来源入队，交回 `SourceDeletionReceipt`；
  `restoreDeletedSource` 只写回来源与库状态。
- `BrowseCraft/Domain/Repositories/SourceRepository.swift`：`SourceDeletionReceipt` 只含来源、库的当前选择与是否入队。
- `BrowseCraft/Infrastructure/Database/Sync/GRDBSourceSyncLocalStore.swift`：写入远端来源删除时只清空库的当前选择。
- `BrowseCraft/Application/UseCases/Source/` 与 `SourcesPersistenceCoordinator.swift`：删除交回留底，撤销写回。
- `BrowseCraft/Features/Sources/SourcesViewModel.swift`、`SourcesView.swift`：可撤销的删除与提示条，删除或撤销成功后递增变更计数。
- `BrowseCraft/App/RootView.swift`：观察变更计数，重新载入历史与收藏。
- 三份 `Localizable.strings`：`sources_footer_hint`。

## 八、测试与验收

- 仓储层：删除来源后三张历史表与收藏都不变、收藏汇总不变；同步队列只有来源的删除（内置来源不入队）；库的当前选择被清空。撤销后来源回到在册、库的当前选择回来，队列里该来源是更新。
- 远端删除：应用远端来源删除后，本机该来源的历史与收藏都不动，库的当前选择被清空。
- ViewModel：来源页删除后，历史页与收藏页重新载入，该来源的条目还在。
- 模拟器：删除一个有历史和收藏的来源，两页的条目变为「来源已删除」、仍能点开；撤销后恢复正常；重新从目录添加同一个来源后也恢复正常。
