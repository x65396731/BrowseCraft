# 删除来源时连带删除历史与收藏

设计与实施状态见 [STATUS.md](../STATUS.md)。数据层的条款定义点在
[数据库说明](../../BrowseCraft/Infrastructure/Database/README.md)「Source 删除规则」（`BCA-DB-004`、`BCA-DB-005`），本文写范围、各条删除路径的处理、
界面与实现清单，不复述条款正文。

## 一、背景

来源页底部一直写着「删除来源会同时删除相关的阅读 / 观看历史和库状态」，代码却只做了软删除来源和清空库的当前选择：
三张历史表与收藏都按「用户快照独立于来源生命周期」的旧规则保留。2026-10-03 用户裁定改为真正连带删除，并把收藏也算进去。
来源页的删除同日已改为不弹确认（[来源页](Sources-Page-Redesign-Design.md) 2.5）；为了不让误触把历史与收藏一起删光，删除后与收藏页、历史页一样在底部给撤销（第四节）。

## 二、删什么、不删什么

用户删除一个来源时，在同一个写事务里：

| 数据 | 处理 |
| --- | --- |
| 来源 | 照旧软删除并写入同步队列（内置来源不入队） |
| 库的当前选择 | 照旧：当前选择正好是它时清空（`BCA-DB-004`） |
| 漫画、视频、书籍三张历史表 | 删除该用户、该来源的全部记录 |
| 收藏 | 该用户、该来源的每条在册收藏写删除标记，逐条写入同步队列，最后重建一次收藏汇总 |
| 临时资源历史 | 不涉及：它没有来源 |
| 站点书续读位置与书签 | 不删：这两张表没有来源列，与「删历史不删续读位置」一致；同一来源重新添加后仍能接着读 |
| 来源的登录凭据 | 不涉及：只存在内存里，重启即失 |

内置来源（`built-in.` 开头）同样连带删除历史与收藏；它本身不入同步队列，但它的收藏删除标记照常入队，否则其他设备会把收藏同步回来。

## 三、各条删除路径

| 路径 | 入口 | 本设计后的处理 |
| --- | --- | --- |
| 用户删除 | 来源页左滑与长按「删除来源」；删除「我的生成」规则（`SourcesViewModel` 删除个人规则时同一条路径） | 按第二节连带删除 |
| iCloud 应用远端删除 | 其他设备删除来源，本机下载到带删除时间的来源记录（`SourceSyncService` 合并后由 `GRDBSourceSyncLocalStore` 写入） | 本地来源由在册变为已删除时，同一事务里删除本机该来源的三张历史表记录，并按 `BCA-DB-004` 清空库的当前选择；收藏不在这里处理——删除的那台设备已把收藏删除标记入队，会经收藏同步到达 |
| iCloud 区域被清除 | 用户在系统设置里清除 iCloud 数据（`GRDBCloudSyncEngineStore` 的清除分支） | 不变：已硬删来源与全部收藏，历史保留 |
| 只用 iCloud 数据 | 登录合并时选择只用云端数据（`GRDBCloudAccountPartitionStore`） | 不变：已硬删来源与全部收藏、清空选择，历史保留 |

后两条是账户级操作，范围与「删一个来源」不同，本设计不改；它们留下的历史仍会以「来源已删除 / 未知来源」显示。

## 四、撤销

用户删除来源后，底部出现与收藏页、历史页同一个反色提示条「已删除「来源名」 · 撤销」（`ContentUndoBanner`），约 4 秒后消失；不弹确认。

- **删除时留底**：删除的写事务把被删内容一并交回——来源记录原样（含启用状态）、删除前库的当前选择（来源 ID 与列表位置）、
  三张历史表被删的全部记录、被写删除标记的收藏条目。
- **撤销时写回**：在一个写事务里把来源恢复为在册（清掉删除时间、更新时间取当前时间），三张历史表记录原样写回（含原访问时间），
  收藏条目恢复为在册并重建汇总；来源（非内置）与每条收藏都以当前时间重新写入同步队列为更新。同步队列按「更新时间较新的更新覆盖较旧的删除」合并，
  所以删除若还没上传，队列里留下的就是更新，云端相当于没变过。
- **当前选择与来源位置**：删除前它是当前来源，撤销后改回当前来源并恢复列表位置；删除时若有已暂停的来源补上了位置，撤销后按位置规则重新归置
  （恢复的来源更新时间最新，回到在用，补位的来源回到已暂停）。
- **推迟同步通知**：删除成功后先不发本地变更通知，等撤销提示消失、被新的撤销提示替换或离开来源页时再发；撤销时不发删除的通知，只在写回后照常通知。
  这样删除在撤销窗口里一般不会被上传。窗口内若被其他时机（回到前台、定时重试）带上去，撤销写回的更新仍会以更新的时间覆盖云端，
  但其他设备若已应用了删除，它们本机的历史已被删掉、不会回来——这是可接受的残余风险。
- **不撤销的**：iCloud 应用远端删除不给撤销；撤销窗口结束、App 被关掉或切走后不能再撤销。

## 五、界面

- 来源页底部说明改为「删除来源会同时删除它的阅读 / 观看历史和收藏。」三语；原确认框留下、已无代码引用的两条文案一并删除。
- 删除与撤销后让历史页、收藏页与库页的收藏状态跟着刷新：`SourcesViewModel` 每删除或撤销成功一次就把一个变更计数加一，
  `RootView` 观察它，重新载入历史与收藏，并让库页刷新当前来源的收藏标记（与收藏页取消收藏后的做法相同）。
- 收藏页、历史页的「来源已删除」「未知来源」两种行保留作兜底：今后主要来自第三节后两条路径、旧版本设备删除的来源，以及本设计之前留下的数据。

## 六、实现位置

- `BrowseCraft/Infrastructure/Database/Repositories/GRDBSourceRepository.swift`：删除来源的写事务里加上删三张历史表、
  逐条给收藏写删除标记并入队（实体 ID 用 `FavoriteItemIdentity` 的同步实体 ID）、调用 `FavoriteAggregateBuilder` 重建汇总；
  删除方法交回被删内容（供撤销），新增按被删内容写回的方法；本地变更通知改由调用方在撤销窗口结束后发（第四节），内置来源只要有收藏变化也要发。
  文件开头与清空选择处两段注释改成新规则。仓储协议 `SourceRepository` 随之调整，测试替身（`ViewModelTestHarness`、`AddComicRuleSourceUseCaseTests` 里的实现）跟着改。
- `BrowseCraft/Infrastructure/Database/Sync/GRDBSourceSyncLocalStore.swift`：写入远端来源记录时，若本地原为在册、远端带删除时间，
  在同一事务里删本机该来源的历史并清空库的当前选择。
- `BrowseCraft/Application/UseCases/Source/` 与 `SourcesPersistenceCoordinator.swift`：删除交回被删内容，新增撤销写回。
- `BrowseCraft/Features/Sources/SourcesViewModel.swift`：保存可撤销的删除与提示停留计时（做法同 `FavoritesViewModel`），撤销、窗口结束后发同步通知，
  删除或撤销成功后递增变更计数。
- `BrowseCraft/Features/Sources/SourcesView.swift`：底部撤销提示条，离开页面时结束撤销窗口。
- `BrowseCraft/App/RootView.swift`：观察变更计数，刷新历史、收藏与库页收藏标记。
- 三份 `Localizable.strings`：改写 `sources_footer_hint`，删掉确认框留下的两条文案。
- 删历史与删收藏写成仓储内的私有 SQL 步骤即可，不新增迁移：三张历史表的唯一键 / 主键都以用户与来源开头，收藏明细表已有按用户与来源的索引。

## 七、测试与验收

- 仓储层：删除来源后，该来源的三张历史表记录清空、其他来源与其他用户的记录不动；该来源的收藏都有删除标记、汇总里不再有它们，
  同步队列里有对应的收藏删除记录；内置来源同样清掉历史与收藏、不产生来源的队列记录。
- 现有 `SyncRepositoryTests` 里删除来源后队列恰有一条的断言仍成立（该测试的来源没有收藏）；若新增收藏，断言要按新规则改。
- 远端删除：`SourceSyncServiceTests` 增加一条——应用远端来源删除后，本机该来源的历史被删、收藏不动、库的当前选择被清空。
- 撤销：删除后撤销，来源回到在册、原来是当前来源的仍是当前来源，三张历史表记录与收藏原样回来（含原访问时间），
  同步队列里该来源与这些收藏的记录都是更新而不是删除；删除正在使用的来源让暂停来源补位后撤销，位置归置回原样。
- ViewModel：来源页删除后，历史页与收藏页重新载入看不到该来源的条目；撤销后又能看到。
- 模拟器：删除一个有历史和收藏的来源，历史页、收藏页、库页的爱心都跟着消失；点撤销后都回来；删除内置来源同样。

## 八、读代码要点

- 删除的留底是 `SourceDeletionReceipt`（`SourceRepository.swift`）。删除路径不在事务后发同步通知，由 `SourcesViewModel.finishUndoableDeletion`
  在撤销窗口结束（超时、被新删除替换、离开来源页、App 切走）时经 `SourcesPersistenceCoordinator.notifyDeletionChanges` 补发；撤销不发删除的通知，`restoreDeletedSource` 写回后自己通知。
- 只有用户在来源页删一个来源可撤销；删除「我的生成」规则与个人规则过期走 `deleteSourcesWithoutUndo`，删完立刻通知。按下标批量删多个也不给撤销。
- 撤销时仓储把删除前的库状态（含列表位置）原样写回，ViewModel 改回当前来源时不再覆盖库状态；库页切换来源本来就会重置分段，
  所以列表位置只在下次启动恢复时体现——这是已知出入，不是缺陷。
- 解不出配置的来源照样删（历史与收藏一并删），只是拿不到留底、不能撤销。
