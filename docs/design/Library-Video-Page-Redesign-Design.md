# 库页视频库的视觉与信息结构重设计

设计稿（画布，含浅色主状态、单列表来源、深色、长按菜单、樱花动漫实际效果、首屏骨架、空、失败、切换来源、分类出错、翻页中、已到底、搜索结果、尺寸与取值，共 14 张）：
[库页视频库重设计](https://claude.ai/artifact/ActT4NEG84Uohnxg6Pj1i6)；设计文档：[库页视频库重设计](https://claude.ai/artifact/PMChdtjBpWHcKYC1pmPvqn)。
设计与实施状态见 [STATUS.md](../STATUS.md)。颜色、圆角、字号与交互约定沿用来源页、规则目录页、收藏页与历史页
（[来源页](Sources-Page-Redesign-Design.md)、[规则目录页](Catalog-Page-Redesign-Design.md)第三节、[收藏页](Favorites-Page-Redesign-Design.md)、
[历史页](History-Page-Redesign-Design.md)），本页不新增色值。

## 一、背景

库页的视频库（`LibraryView` + `VideoContentGridView`）是底栏五页里最后一页还没按统一语言重做的。它左邻收藏页、右邻历史页，
两边都已是自绘大标题与圆角 18 的卡片，切到库页反差最明显：

- 导航栏是系统 inline 标题「樱花动漫 · 日本动漫」；左上一个放大镜把搜索与登录塞进同一个菜单。
- 分类条是圆角 6 的矩形芯片，选中色是写死的 #8599FF 蓝紫，与视频类型色（琥珀）无关；标题色也是一处写死的 `libraryTitleText`。
- 三列网格、封面圆角 6、12pt 粗体标题；「更新到第 N 集」是同一种蓝紫小字——集数是视频列表最有用的信息，却最不显眼。
- 每张封面右上都压一个黑圈爱心，一屏九张卡片九个圈。
- 「第 1 页 · 滑到底部继续加载」是一枚常驻的黑色胶囊，悬浮在底栏上方，挡住最后一行标题。
- 上次看到哪部、看到第几集，要去历史页才知道；库页与历史页之间没有通路。
- 三种类型共用同一套网格（书籍复用漫画卡片），只换占位图，看不出这是视频库还是漫画库。

## 二、入口、相邻页面与范围

本页是底栏第三个标签「库」，有来源时冷启动直接落到这里。来源页「点来源即打开库」、收藏页与历史页长按「在库中查看来源」都切到本页
（`RootView` 的 `openSourceInLibrary`）。

- **出口**：点海报进 `VideoDetailView`（头图 + 简介 + 选集，隐藏底栏、自带返回）；「上次看到」瓷砖直接开全屏播放器，与历史页点行同一条路径；
  左上搜索弹出 `LibrarySearchView`；账号按钮打开来源登录页 `SourceLoginView`。
- **相邻**：左邻收藏页、右邻历史页，两页都是封面卡片行。本页是封面的源头，三页共用同一条封面管线（`ItemThumbnailImageView`）与同一套类型徽标。
- **范围**：库标签三种类型各用一种版式——视频海报墙、漫画、书籍各自立项，本文只定视频：顶部、分类条、「上次看到」瓷砖、海报墙、分页提示与各状态。
  `LibraryView` 的外壳（顶部、分类条、状态页、切换来源遮罩）三种类型共用，本次一并改；漫画与书籍的网格本次不动，等各自的设计。
- **不在范围**：影视详情页、播放器、来源登录页、搜索页的外壳（搜索结果复用本页网格，所以会跟着变）。

## 三、页面结构

页面跟随系统深浅，底色取页面底，隐藏系统导航栏。从上到下：

| 顺序 | 块 | 内容 | 什么时候出现 |
| --- | --- | --- | --- |
| 1 | 顶部 | 标题上方一行小字「▶ 视频 · 主机名」（播放三角取视频类型色）；大标题 = 来源名，`largeTitle` heavy，最多两行；右侧两个 40pt 圆形按钮：搜索（放大镜）、账号（人形，登录后实心） | 一直；搜索按钮只在规则声明可搜索时，账号按钮只在来源需要登录时 |
| 2 | 分类条 | 横向滚动的胶囊芯片，选中段视频类型色底；作为贴顶的分区头，滚到顶时留在标题位置 | 来源有两个以上列表页时 |
| 3 | 上次看到 | 视频类型色的深色瓷砖：封面 72×100、「上次看到」、作品名、「第 N 集 · 看到 23:14 / 45:00」、进度条、时刻；点了直接进播放器 | 当前来源有视频历史时；在滚动内容里，随内容滚走 |
| 4 | 分类出错横幅 | 警示色淡底一行：图标 + 错误原因 | 有内容但当前分类报错时 |
| 5 | 海报墙 | 两列、列距 14、行距 20；封面 2:3、圆角 14；集数徽章压封面左下、爱心压右上；标题两行在封面下 | 有内容时 |
| 6 | 分页脚 | 网格下方一行居中小字：转圈 +「第 N 页 · 正在加载下一页」/「第 N 页 · 滑到底部继续加载」/「第 N 页 · 已加载到底」 | 规则支持分页且有内容时 |
| — | 骨架 / 空 / 失败 / 切换来源 | 见第七节 | 对应状态时整页只出一种 |

下拉刷新当前分类第 1 页、滑到底加载下一页，两条路都不变。页边距左右 20pt。

## 四、海报卡片

一张卡片只有封面与标题两层；集数与收藏态都压在封面上，标题下不再有第二行。

| 位置 | 内容 | 取值 |
| --- | --- | --- |
| 封面 | 2:3，宽随两列算出（iPhone 17 Pro 约 170×255pt）；`ItemThumbnailImageView` 走现有封面管线，请求配置取规则的图片请求配置；无封面退回 `VideoListPlaceholder` | 圆角 14，不描边、不投影 |
| 封面左下 · 集数徽章 | `latestText`（「更新至第 12 集」「完结」…）做成胶囊徽章，一行可截断；没有 `latestText` 就不出徽章 | 固定色：底 `bannerAccent` #F2A65A、字 `bannerIconInk` #141210，`caption2` bold，高 20、左右 8、离封面边 8；与类型横幅的图标圆同一做法 |
| 封面右上 · 爱心 | `TabFavorites` / `TabFavoritesOutline` 18pt 在 32pt 圆里；未收藏白色空心，已收藏实心用视频强调色 #F2A65A（不再用粉色） | 圆底黑 40%；热区 44pt；点了即收藏 / 取消，不弹确认 |
| 标题 | 作品名 `subheadline` semibold，主文字色（不再用 `libraryTitleText`），两行定高，同一行的卡片底边对齐 | 封面下 8pt |
| 整张卡片 | 点 = 进影视详情；长按菜单「打开」「收藏 / 取消收藏」，预览按封面圆角裁 | 按下时整卡变淡（系统 plain 按钮样式） |

- 每屏大约 4–6 张海报（现在是 9 张）：海报是视频列表的主要识别信息，换密度换来读得清的封面和集数；漫画库标题多、靠章节名识别，
  将来可以保留三列，两种密度本身就是两种版式的区别。
- iPad 与横屏：列数按最小宽 160pt 自适应，列距行距不变。
- 搜索结果复用同一张卡片与同一套网格。

## 五、顶部与分类条

**顶部**（在滚动内容里，随内容滚走）：

- 眉行「▶ 视频 · 主机名」：`caption` 次级色，播放三角取视频 `accent`；主机名取 `CatalogDisplayText.displayHost`。三种类型三种版式之后，眉行是最便宜的「这是视频库」提示。
- 大标题 = 来源名，`largeTitle` heavy，最多两行、可缩到 0.8；来源名本身可能带同站副标题（「樱花动漫 · 日本动漫」），照原样显示。
- 右侧按钮：40pt 圆、卡片底色、图标 `headline` semibold 主文字色，与大标题底边对齐。搜索与账号拆开，各自只在可用时出现；登录后账号图标实心；
  长按账号按钮弹菜单「打开登录页」「退出登录」（红）。两个都没有时标题占满宽。
- 没有来源时照现状落到来源页，本页不画「没有来源」空状态。

**分类条**：

- 胶囊芯片，高 36、左右 16，`subheadline`；未选中 `fillBackground` 底 + 主文字；选中视频类型色底——浅色 #A85A12 底白字、深色 #F2A65A 底 `bannerIconInk` 字，
  两者对比度都不低于 4.5:1。芯片间距 8，横向滚动，首尾留 20。
- 以 `LazyVStack` 的 pinned 分区头贴顶：标题滚走后芯片留在顶部，底下铺页面底色，不加分隔线。
- 切分类只换网格内容，不动眉行与大标题；切换中被点的芯片先变色，网格按现状走骨架或留旧内容。
- 同一套芯片给漫画与书籍：换 `CatalogKindStyle` 即换色，不再像现在的 `LibraryListTabBar` 那样写三份几乎相同的芯片代码。

## 六、「上次看到」瓷砖

当前来源在视频历史里有记录时，网格上方放一张瓷砖，让「接着看」不用绕到历史页。这是本设计唯一的新接线。

- **条件**：按来源 ID 过滤视频历史、取访问时间最近一条。切换来源时重取；从播放器回到库页时刷新（播放器 `fullScreenCover` 的关闭回调与库页 `onAppear` 重读）。它属于来源、不属于分类，切分类不影响。
- **样子**：与历史页继续卡片同一个 `HistoryContinueTileView`：`.sourceTile(style:)` 视频深色底 #2B2117 + 右上琥珀光圈，圆角 24；左封面 72×100、圆角 12、徽标 `.tile`；
  右侧从上到下琥珀小字「上次看到」、作品名 `headline` bold 两行、「第 12 集 · 看到 23:14 / 45:00」（没有时长只写「看到 23:14」，95% 以后写「已看完」）、
  4pt 进度条、底行只写时刻（「今天 21:30」「昨天」「M月D日」）——来源名已是大标题，不重复。
- **点击**：整张瓷砖 = 直接开全屏播放器，与历史页点行同一条路径；长按菜单「继续看」「打开作品」（进详情选集）。不在这里删历史，那是历史页的事。
- **不出现**：没有视频历史、来源切换中、搜索页。骨架 / 空 / 失败态下有历史照样显示（本地读取，不等网络）——列表取不到时还能接着看。
- **数据**：`LibraryViewModel` 现在不读历史；新增一个只读查询，复用历史页读视频历史的仓储，按来源过滤取最近一条；封面请求配置与网格同一个。
  漫画与书籍将来用同一个查询换类型即可（「上次读到」）。

## 七、其余状态

正文同一时刻只出一种版面（`LibraryBodyState` 不动）；眉行、大标题、分类条与「上次看到」瓷砖在所有状态下照常。

| 场景 | 显示 |
| --- | --- |
| 首屏加载 | 骨架与海报墙同形：两列封面色块（圆角 14）+ 两行标题条，呼吸动画；`LibrarySkeletonGridView` 改形，批数 6 张 |
| 取回来是空的 | `LibraryPlaceholderView`：插画 `EmptyStateLibraryVideo`（看板娘举遥控器对着一块只有播放三角的空白银幕，本页自己的图，不再借用搜索页的放大镜）+「还没有内容」+ 一句说明 +「下拉可重新载入」，在滚动内容里撑满视口 |
| 第 1 页失败 | 同上，插画 `EmptyStateOffline` +「载入失败」+ 错误原因 +「下拉重试」 |
| 有内容但本分类报错 | 警示色淡底（`warningFill`）圆角 16 横幅：警示色三角 + 原因，在网格上方；不再用系统橙 |
| 切换来源 | 旧列表留在屏上，盖一层页面底 82%，居中一张 `StatusCardView` 进行中样式（转圈 +「正在切换来源」+「正在从 X 取最新内容」）；眉行与大标题先换成新来源 |
| 翻页中 | 分页脚：转圈 +「第 N 页 · 正在加载下一页」 |
| 还有下一页 | 分页脚：「第 2 页 · 滑到底部继续加载」次级色 |
| 已到底 | 分页脚：「第 N 页 · 已加载到底」 |
| 下拉刷新 | 系统下拉控件；刷新中网格不换骨架 |
| 来源需要登录 | 账号按钮空心；列表照规则给的结果显示，不另画「请登录」卡（现状） |

深色模式：页面底、卡片底、芯片随系统；瓷砖与集数徽章是固定深色取值，两种模式下一样。

空状态插画 `EmptyStateLibraryVideo` 与其余空状态插画同规格（同一个看板娘、即梦出图、透明底、540px 高、按 180pt 显示，画面内不含文字）；
即梦设定与提示词在画布「视频库空状态插画 · 即梦设定」画板。失败态继续用各页共用的 `EmptyStateOffline`。

## 八、每个元素的数据来源与缺省

画布第一张是「所有可选元素都在」的合成图；每个元素都是有数据才显示，没有就整块不出、不留空位。

| 元素 | 数据来源 | 没有时 | 立项时按三个视频来源核对的现状 |
| --- | --- | --- | --- |
| 集数徽章 | 列表规则可选字段 `latestText`（`DefaultVideoListRuleParser` 取出，站点原文） | 不出徽章 | 樱花动漫 3 个列表都没有；威视TV 6 个列表都有；看片狂人有。fwq 只在覆盖率过门槛才发布，记为部分覆盖。文字可能是「更新至12集」「完结」也可能是「HD」，App 不改写 |
| 「上次看到」瓷砖 | 视频历史表 `VideoWatchHistory`：集名、播放位置、时长、封面、来源、访问时间 | 不出瓷砖；没有时长只写「看到 23:14」、不画进度条；还没播起来只写集名 | 字段都在，历史页继续卡片用的就是这一套 |
| 分类芯片 | 列表规则个数 ≥ 2 | 不出分类条 | 樱花 3 个、威视 6 个有；看片狂人 1 个没有 |
| 搜索按钮 | 规则声明 search（`selectedSourceSupportsSearch`） | 不出按钮 | 樱花、威视有；看片狂人没有 |
| 账号按钮 | 来源有登录 / 凭据配置（`selectedSourceLoginState`） | 不出按钮 | 三个来源都没有 |
| 大标题 / 眉行主机名 | `Source` 的名称与 `baseURL` | — | 都有 |
| 封面 | 列表规则 `cover` | 退回 `VideoListPlaceholder` | 三个都有 |
| 分页脚 | 现有 `shouldShowPaginationStatus` / `paginationStatusText` | 规则不支持分页时不出 | 都有 |

所以樱花动漫实际看到的是：有芯片、没有任何徽章、只有搜索一个圆按钮、看过一集后才有瓷砖（画布第一行最右）。`latestText` 覆盖率低是 fwq 侧的事，App 不改规则、只按有无显示。

## 十、裁定

2026-10-07 用户裁定七项全取 A：两列海报墙；加「上次看到」瓷砖；分页提示收进网格底部、去掉悬浮胶囊；横向滚动胶囊芯片贴顶；
保留封面爱心、已收藏用视频强调色；搜索与账号拆成两个圆形按钮；不加来源切换（留在来源页）。

## 十一、不改的东西

- 列表数据、分页（`startPage` 代入）、分类缓存、切换来源、收藏切换、搜索、登录与凭据——本设计只改信息组织与外观，外加「上次看到」一个只读查询。
- `LibraryBodyState` 的五种状态与优先级；下拉刷新与触底加载两条路。
- 影视详情页、播放器、搜索页外壳、来源登录页。
- 漫画与书籍的网格与卡片（`ComicLibraryCardView`）本次不动。
- App 不提供规则创建或编辑入口（`BCA-UI-003`）；`latestText` 等字段有无由规则决定。

- `BrowseCraft/Features/Library/Video/List/VideoContentGridView.swift`：两列海报墙与海报卡片（集数徽章、爱心、长按菜单）。
